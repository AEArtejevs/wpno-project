## TITLE

Broad-pattern false positives on a real article corpus

## RISK

```text
HIGH
```

## OBJECTIVE

Measure the checker's true positives, false positives, true negatives and false negatives against a real corpus with independent labels, and identify the specific patterns that are overbroad.

## WHY THIS MATTERS

CLAUDE.md § 10 records a counter that found three of ten citations and then reported that all citations were supported. Precision and recall are separate questions and a single accuracy figure hides both. A pattern that is broad enough to be safe is also broad enough to be ignored.

## THREAT MODEL

Labelling the corpus with the tool under test, which guarantees a perfect score and measures nothing. Using a synthetic corpus built for a different component, which measures the fixture author rather than the tool.

## STATIC ANALYSIS

No module under `PROJECT_ROOT` may be imported. A top-level import executes code. Parse; do not import.

1. Extract the checker's pattern set by AST parse: every regex, its flags, its anchors and its boundary constructs.
2. Classify patterns by breadth: unanchored, short, or matching a common word form.
3. Record explicitly that ap18/korpus and ap18/korpus_docx are synthetic fixtures built for the input filter and are NOT a real article corpus. Using them would answer a different question.

## RUNTIME TEST MATRIX

Every runtime operation below is gated and requires the human approval token. Nothing here runs before that token arrives.

1. Locate the operator-supplied corpus in references/ (REF-07). Verify hashes against references/manifest.json. If absent: UNVERIFIED, and say why.
2. Record the corpus origin, document count, total length and per-document hashes.
3. Produce independent labels: enumerate the citations a reader would identify, by a method that does not involve running the checker. Record the labelling method and who or what produced the labels.
4. Run the checker over the corpus. Record raw output.
5. Build the confusion matrix: TP, FP, TN, FN. Report all four counts; never a single score.
6. Attribute every false positive to the specific pattern that produced it.
7. Attribute every false negative to the absent or too-narrow pattern.
8. Report separately the citations the checker never examined at all — this is a third category, and it is not the same as a false negative.

## POSITIVE CONTROL

A document containing a citation of a form the checker is known to handle must yield a true positive.

## NEGATIVE CONTROL

A document containing no citation at all must yield no hits. If it does, the pattern set matches ordinary prose.

## MUTATION CONTROL

Narrow one overbroad pattern in a sandbox copy and re-run. The false-positive count attributed to it must fall. This proves the attribution is correct.

## INDEPENDENT ORACLE

The independent labels (REF-07), produced without the checker. The checker may never label its own evaluation corpus.

Forbidden as an oracle for this audit: the implementation under test, any other copy of it, any project artefact derived from it, any prior report under `docs/`, this package's own reconciliation notes, any output of the failed predecessor package, and model knowledge unsupported by a retrieved source.

## EDGE CASES

- a citation inside a quotation of another document
- a citation in a footnote

## PASS CRITERIA

A real labelled corpus was used; all four counts are reported; every false positive and false negative is attributed to a pattern; the never-examined category is reported separately; controls hold.

In addition, and without exception: positive control passed, negative control passed, mutation control passed where applicable, independent oracle used, target hash unchanged across the run, and no unresolved evidence capable of changing the conclusion. If such evidence exists the verdict is `UNVERIFIED`, not `PASS`.

## PASS_WITH_WARNINGS CRITERIA

False positives exist and are all attributed to patterns whose breadth is documented and deliberate.

Every warning is named with its own evidence. A warning is not a place to put doubt about the main conclusion — that belongs in `UNVERIFIED`.

## FAIL CRITERIA

An overbroad pattern produces false positives on ordinary prose, or a class of citation is never examined while the tool reports completeness.

## BLOCKED CRITERIA

The checker cannot be run.

A blocked audit is a legitimate and complete outcome. State precisely what is missing and what would unblock it. Never soften BLOCKED into PASS or into a partial pass.

## UNVERIFIED CRITERIA

No real corpus was supplied. This is the expected verdict today. Say so; do not substitute the synthetic corpus.
