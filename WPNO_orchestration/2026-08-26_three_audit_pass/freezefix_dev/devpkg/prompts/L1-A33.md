## OBJECTIVE

Compare the container's XML metadata, file names, timestamps, declared hashes, actual hashes, manifests, signed artefacts, message metadata, sender and recipient references, and chronology — and give evidence for every contradiction found.

## WHY THIS MATTERS

A transport container carries its own account of what it contains. Where that account disagrees with the bytes, the disagreement is the evidence. A contradiction asserted without both sides shown is an allegation.

## STATIC ANALYSIS

No module under `PROJECT_ROOT` may be imported. A top-level import executes code. Parse; do not import.

1. Locate the container and 563203462.xml in references/ (REF-11). If absent: BLOCKED. Neither exists in any Discovery scan root.
2. Configure the XML reader before reading anything: external entities disabled, DTD processing disabled, network access disabled, XInclude disabled unless the format requires it and the requirement is documented.
3. Record the reader configuration in the evidence. A parse performed without this configuration is not usable and must be redone.
4. List the container's entries without extracting.
5. Parse the manifest and record every declared entry with its declared hash, size and name.

## RUNTIME TEST MATRIX

Every runtime operation below is gated and requires the human approval token. Nothing here runs before that token arrives.

1. Compute the actual hash of every entry over the byte range the manifest specifies. State the range.
2. Compare declared against actual for every entry. Report matches and mismatches as separate lists.
3. Compare file names as declared against names as stored, including Unicode normal form.
4. Compare timestamps from three sources separately: the XML metadata, the archive entry headers, and the filesystem. Never merge them — a copy operation rewrites one and not the others, and the difference is informative.
5. Record sender and recipient references and check them for internal consistency across the metadata and the signed artefacts.
6. Build the chronology from the timestamps and identify any ordering that is impossible.
7. For every contradiction: state the two sides, their sources, their byte-level values, and why they cannot both be true.

## POSITIVE CONTROL

Take an entry whose declared and actual hash agree and confirm the method reports agreement.

## NEGATIVE CONTROL

Alter one byte of an entry in a sandbox copy and confirm the method reports the mismatch.

## MUTATION CONTROL

Alter a declared hash in a sandbox copy of the manifest and confirm the mismatch is detected from that side too. This proves both sides of the comparison are live.

## INDEPENDENT ORACLE

The container's own bytes, read with a safely configured parser, and independent hash computation. The container's metadata is one side of the comparison and never the arbiter.

Forbidden as an oracle for this audit: the implementation under test, any other copy of it, any project artefact derived from it, any prior report under `docs/`, this package's own reconciliation notes, any output of the failed predecessor package, and model knowledge unsupported by a retrieved source.

## PASS CRITERIA

All entries are compared; the parser configuration is recorded; contradictions are enumerated with both sides and their sources; and no contradiction is asserted without evidence.

In addition, and without exception: positive control passed, negative control passed, mutation control passed where applicable, independent oracle used, target hash unchanged across the run, and no unresolved evidence capable of changing the conclusion. If such evidence exists the verdict is `UNVERIFIED`, not `PASS`.

## PASS_WITH_WARNINGS CRITERIA

No content contradiction is found and timestamps from different sources disagree in a way explainable by a copy operation. State the explanation as a hypothesis, not a conclusion.

Every warning is named with its own evidence. A warning is not a place to put doubt about the main conclusion — that belongs in `UNVERIFIED`.

## FAIL CRITERIA

A declared hash does not match the actual content, or the metadata is internally inconsistent in a way that bears on authenticity.
