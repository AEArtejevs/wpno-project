## OBJECTIVE

First establish exactly what 376 refers to. Only after that: hash its exact raw bytes with two independent methods and record path, size, source, chain of custody and the expected comparison value.

## WHY THIS MATTERS

A number used as a name in an earlier report is not a target. Hashing something that might be what 376 meant produces a hash of something, attributed to something else, and that attribution error survives into every later document that cites it.

## POSITIVE CONTROL

Verify both hashing methods against a file of known hash.

## NEGATIVE CONTROL

Verify both methods distinguish two different files.

## MUTATION CONTROL

Alter one byte in a sandbox copy and confirm both methods detect it.

## INDEPENDENT ORACLE

Two independent hashing methods, plus the operator's stated expected value with its provenance.

Forbidden as an oracle for this audit: the implementation under test, any other copy of it, any project artefact derived from it, any prior report under `docs/`, this package's own reconciliation notes, any output of the failed predecessor package, and model knowledge unsupported by a retrieved source.
