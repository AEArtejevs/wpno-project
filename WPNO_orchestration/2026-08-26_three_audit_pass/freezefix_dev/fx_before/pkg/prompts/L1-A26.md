## STATIC ANALYSIS

No module under `PROJECT_ROOT` may be imported. A top-level import executes code. Parse; do not import.

1. Enumerate the nine classes verbatim with line numbers. They are: (1) word boundary forgotten, *bea* matching Bearbeitung; (2) regex without +, Schriftschluessel /F1+0; (3) one court's rule applied to all; (4) test with exit 0 that checks nothing; (5) a counter that counts only what it knows; (6) find -name A -o -name B without parentheses; (7) a check that counts itself; (8) green tests that never touch the new code; (9) the same file in several places.
2. For each: state the exact definition as written, then search the tree for an implementation that detects that class, for its caller, and for a test of it.
3. Record 'no detection found' explicitly where that is the result. That is the most likely and most important finding for several classes.
4. For class 9, compare the claim of four payload_scan copies against the actual count. This build observed six files with four distinct contents; re-derive it independently.
5. For class 3, the three real case numbers named in the text (20 F 15/22, I-25 U 75/25, 16 U 139/23) are a ready-made test set for the citation checker — cross-reference with L1-A13.

## RUNTIME TEST MATRIX

Every runtime operation below is gated and requires the human approval token. Nothing here runs before that token arrives.

1. For each class where a detection implementation exists, construct a positive example that must be detected and a negative example that must not be.
2. Run them against that implementation and record the result.
3. Where no implementation exists, record the class as undetected and construct the examples anyway, so that a future implementation has a test set.
4. For each class assess the false-positive risk (what legitimate content would trip it) and the false-negative risk (what real instance would evade it).
