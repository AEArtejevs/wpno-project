## OBJECTIVE

Enumerate every SignerInfo in the CMS structure, map each to its certificate, and record for each the identifier, digest algorithm, signature algorithm, signed attributes, messageDigest, verification result, and any countersignature or timestamp.

## WHY THIS MATTERS

Tools display the first signer. A structure with two signers where the first verifies and the second does not will be reported as verified by any inspection that stops at index zero. The second signer is exactly where an anomaly would sit.

## THREAT MODEL

Inspecting only the first SignerInfo. Assuming all signers share a digest algorithm. Treating a countersignature as a second signer, or a second signer as a countersignature. Reporting one aggregate verification result for a structure with several.

## STATIC ANALYSIS

No module under `PROJECT_ROOT` may be imported. A top-level import executes code. Parse; do not import.

1. Locate the CMS object in references/ (REF-11). If absent: BLOCKED.
2. Parse the structure and count the SignerInfo entries before doing anything else. Record the count explicitly; it is the fact this audit exists to establish.
3. For each SignerInfo record: the signer identifier (issuer and serial, or subject key identifier), the digest algorithm, the signature algorithm, the complete signed attribute set, and the messageDigest value.
4. Enumerate the certificates carried in the structure and map each SignerInfo to one. Record any SignerInfo with no matching certificate — that is a finding.
5. Identify countersignatures and timestamp tokens, and record them as such rather than as signers.

## RUNTIME TEST MATRIX

Every runtime operation below is gated and requires the human approval token. Nothing here runs before that token arrives.

1. Verify each SignerInfo independently. Record per signer: the exact argv, the exit code, and the result.
2. Never report an aggregate. A structure with three signers gets three results, and the summary states how many verified.
3. For each timestamp token present, record its authority, its time, and whether it was verified — and treat verification of the token as a separate question from verification of the signature it covers.
4. Use no suppression flag anywhere. Mark any parse-only result PARSE_ONLY_NOT_VERIFICATION.

## POSITIVE CONTROL

Construct a synthetic CMS structure with two signers, both valid, and confirm the enumeration finds two and verifies both. This proves the enumeration does not stop at the first.

## NEGATIVE CONTROL

Construct a synthetic structure with one signer and confirm the method reports exactly one.

## MUTATION CONTROL

In a synthetic two-signer structure, corrupt the second signature. The method must report the first as verifying and the second as failing. If it reports overall success, it is stopping at index zero.

## INDEPENDENT ORACLE

The ASN.1 structure read directly, independent of any high-level tool that might summarise. Synthetic structures with a known signer count.

Forbidden as an oracle for this audit: the implementation under test, any other copy of it, any project artefact derived from it, any prior report under `docs/`, this package's own reconciliation notes, any output of the failed predecessor package, and model knowledge unsupported by a retrieved source.

## EDGE CASES

- a signer whose certificate is not carried in the structure
- two signers with different digest algorithms
- a countersignature attached to one signer only
- a timestamp token from an authority whose certificate is absent
- a signer with an unsigned attribute set

## PASS CRITERIA

Every SignerInfo is enumerated and mapped to a certificate; each is verified separately with its own recorded result; countersignatures and timestamps are identified as such; and no aggregate result replaces the per-signer results.

In addition, and without exception: positive control passed, negative control passed, mutation control passed where applicable, independent oracle used, target hash unchanged across the run, and no unresolved evidence capable of changing the conclusion. If such evidence exists the verdict is `UNVERIFIED`, not `PASS`.
