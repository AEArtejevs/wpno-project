## OBJECTIVE

Establish how many tests are collected, how many execute, how many meaningful assertions run, and whether the test can fail at all — then prove it detects a controlled mutation.

## WHY THIS MATTERS

This project has already shipped this exact defect twice. CLAUDE.md § 10, class 4: two test functions, no __main__ block, so a direct call merely defines them and exits 0. Class 8: pytest reported 5 passed while no test file mentioned the 130 new lines of the PII filter. An exit code of 0 from a test that ran nothing is the most dangerous artefact in a QA system, because it is filed as evidence of correctness.

## THREAT MODEL

Exit 0 with zero collected. Exit 0 with tests collected but all skipped or xfailed. Tests that execute but assert nothing. Tests that import a different module than the one they claim to test. A file that is never collected because its name or location does not match the configuration.

## STATIC ANALYSIS

No module under `PROJECT_ROOT` may be imported. A top-level import executes code. Parse; do not import.

1. AST-parse the test file. Count: test functions by name convention, assert statements per function, pytest.raises blocks, and any assertion helper calls.
2. Determine whether a __main__ block exists. Its absence, combined with an invocation style of 'python3 file.py', is the documented class-4 defect.
3. Determine what the test imports and whether it is the code under test. Compare the imported module path against ap18/AP18_eingangsfilter.py.
4. Read pytest.ini: testpaths are anonymization, docker, orchestrator. ap18 is not among them, and AP18_test_injection.py matches neither default python_files pattern. Both facts must be verified, not inherited from this prompt.
5. Enumerate skip and xfail markers, fixtures, and any conditional that could disable a test silently.

## RUNTIME TEST MATRIX

Every runtime operation below is gated and requires the human approval token. Nothing here runs before that token arrives.

1. PYTEST_COLLECT_SANDBOX against a sandbox copy of the tree. Record the collected count and the full collection report, including collection errors.
2. If zero collected: that is the primary finding. Record it, and continue to establish why.
3. PYTEST_RUN_SANDBOX with verbose output. Record collected, executed, passed, failed, skipped, xfailed, errored.
4. Record assertion counts where determinable, by static count cross-checked against runtime behaviour.
5. Invoke the file directly the way a person would (python3 AP18_test_injection.py) and record the exit code and whether anything actually ran. An exit 0 that defines functions without calling them is the defect in its original form.
6. Introduce a controlled mutation into a sandbox copy of ap18/AP18_eingangsfilter.py — invert one detection condition — and re-run. The test must fail.
7. If the test still passes after the mutation, it does not test the filter, and that is the finding regardless of how many tests are green.
