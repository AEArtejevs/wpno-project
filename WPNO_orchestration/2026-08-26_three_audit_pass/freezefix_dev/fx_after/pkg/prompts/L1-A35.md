## OBJECTIVE

Test the hypothesis that the copy operation on 17.08 caused the damage, by distinguishing every byte layer involved and testing the hypothesis against the signature's actual cryptographic coverage boundary.

## WHY THIS MATTERS

The intuitive argument runs: the signature verifies, therefore nothing the copy did matters. That argument is wrong whenever the damage lies outside the signature's coverage — in archive metadata, in filesystem attributes, in entries a macOS copy added. A signature proves things about the bytes it covers and nothing whatever about the bytes it does not. The whole question is where that line falls.

## THREAT MODEL

Concluding from a valid signature that copying is excluded. Comparing the wrong layers — a container hash against a content hash — and calling the difference damage. Relying on filesystem timestamps that the copy itself rewrote. Assuming a single 'the file' when there are at least six distinguishable byte layers.

## STATIC ANALYSIS

No module under `PROJECT_ROOT` may be imported. A top-level import executes code. Parse; do not import.

1. Locate the source copy, the destination copy and the copy metadata in references/ (REF-11). If any is absent: BLOCKED. The hypothesis cannot be tested against one side.
2. Enumerate the layers explicitly and keep them separate throughout: (1) raw file bytes; (2) container bytes; (3) signed content bytes; (4) archive metadata (central directory, entry order, compression parameters, stored timestamps); (5) filesystem metadata (mtime, ctime, xattrs, resource forks, quarantine attributes); (6) post-signing container additions such as AppleDouble entries.
3. For each layer, state in advance how it would be measured and what a difference in it would and would not imply.
4. Obtain the signature's coverage boundary from L1-A34. Without it, no layer can be classified as inside or outside coverage, and the audit cannot conclude.

## RUNTIME TEST MATRIX

Every runtime operation below is gated and requires the human approval token. Nothing here runs before that token arrives.

1. Hash source and destination at every layer separately. Record twelve values, not two.
2. Compare per layer. Produce a table: layer, source value, destination value, equal, inside signature coverage.
3. Record copy timestamps from all available sources and note which the copy operation itself would have rewritten.
4. Detect recompression: compare compression method and compressed sizes per entry between source and destination. Identical content with different compressed sizes is recompression, and it changes the container while leaving the content intact.
5. Detect AppleDouble and macOS metadata additions (L1-A30) and place them in the layer table.
6. For every difference found, state: which layer, whether it is inside the signature's coverage, and therefore what it does and does not prove.
7. State the two conclusions separately and explicitly: what the signature proves, and what the signature does not prove. The second is the substance of this audit.

## POSITIVE CONTROL

Copy a synthetic archive in the sandbox with a method known to preserve bytes exactly, and confirm every layer compares equal. This proves the comparison does not manufacture differences.

## NEGATIVE CONTROL

Copy a synthetic archive with a method known to recompress, and confirm the container layer differs while the content layer does not. This proves the layers are genuinely separated.

## MUTATION CONTROL

Alter one byte inside the signed content of a synthetic copy and confirm that the content layer differs and the signature fails. Then alter one byte of archive metadata outside coverage and confirm the content layer is unchanged and the signature still verifies. These two together are the demonstration that the coverage boundary is real and correctly located.

## INDEPENDENT ORACLE

Layer-by-layer independent hashing plus the coverage boundary established in L1-A34. The signature's verification result is one input to the analysis, never its conclusion.

Forbidden as an oracle for this audit: the implementation under test, any other copy of it, any project artefact derived from it, any prior report under `docs/`, this package's own reconciliation notes, any output of the failed predecessor package, and model knowledge unsupported by a retrieved source.

## EDGE CASES

- a copy that preserved content and changed entry order
- a copy that added a resource fork
- a copy through a filesystem that does not support extended attributes
- a copy that normalised filenames to a different Unicode form
- a copy made after an unrelated modification, so two causes overlap

## PASS CRITERIA

Every layer is measured separately on both copies; differences are classified as inside or outside the signature's coverage; and the hypothesis is answered with the coverage boundary stated. A PASS here means the analysis was performed correctly, not that copying was harmless.

In addition, and without exception: positive control passed, negative control passed, mutation control passed where applicable, independent oracle used, target hash unchanged across the run, and no unresolved evidence capable of changing the conclusion. If such evidence exists the verdict is `UNVERIFIED`, not `PASS`.

## PASS_WITH_WARNINGS CRITERIA

Differences exist outside the coverage boundary and their practical significance depends on facts not available offline. State which facts.

Every warning is named with its own evidence. A warning is not a place to put doubt about the main conclusion — that belongs in `UNVERIFIED`.

## FAIL CRITERIA

Differences exist inside the coverage boundary — the copy changed signed content — or the available evidence cannot exclude that.

## BLOCKED CRITERIA

Source, destination or copy metadata is not supplied, or L1-A34 has not established the coverage boundary. This is the expected verdict today.

A blocked audit is a legitimate and complete outcome. State precisely what is missing and what would unblock it. Never soften BLOCKED into PASS or into a partial pass.

## UNVERIFIED CRITERIA

Layers are compared and the coverage boundary cannot be established, so no difference can be classified.
